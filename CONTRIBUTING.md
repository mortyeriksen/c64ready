# Contributing to C64 READY.

Thanks for taking an interest. Bug reports, fixes and improvements are all welcome.

## Reporting a problem

Open an issue on [GitHub](https://github.com/mortyeriksen/c64ready/issues). Please include:

- what you loaded (`.d64`, `.prg`, `.tap`, `.crt`, ...) and where it came from, if it is freely available
- what you expected and what happened instead; a screenshot or short recording helps
- browser and OS (and phone model, if on mobile)

Check [Known issues](docs/KNOWN-ISSUES.md) first; it may already be listed.

## Setting up

You need **Node.js 20.19+ or 22.12+** (22 LTS or newer recommended) and your own C64 ROMs
(`kernal.bin`, `basic.bin`, `chargen.bin`, and `1541.bin` for the true drive) in `roms/`.
ROMs are not part of this repository.

```bash
npm install
npm run dev     # dev server
npm test        # the full test suite
npm run build   # production build
```

See [Getting started](docs/GETTING-STARTED.md) and [Testing](docs/TESTING.md) for more.

## Making changes

- Keep a pull request to one thing. Small, focused changes are easier to review.
- Run `npm test` before you open it; the suite should pass.
- Add a test when you fix or change behaviour. New test files go in `test/`, are named
  `*-test.js`, and must be added to the `TESTS` array in `test/all-test.js` to run.
- Emulation changes should be backed by hardware behaviour. Cite the source you worked
  from (see [Specifications & sources](docs/SPECIFICATIONS.md)); a fix that makes one
  demo look right but is not how the chip works will not hold up.
- Do not add demo or game binaries to the repository. Tests use synthetic programs.
- Browser code in `src/` must not read `process.env`; use `src/switches.js`.
- Documentation lives in `docs/*.md`. `public/docs/` is generated by `npm run build:docs`,
  so edit the Markdown, not the output.
- Start new source files with the two-line SPDX/copyright header used in `src/`, `docs/`
  and `tools/`. Test scripts under `test/` do not need it.
